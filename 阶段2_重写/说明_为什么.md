## 四、每个部件为什么存在

### 4.1 为什么 API Key 不能写进代码

- 一旦写进 `.py`，`git commit` 就永久留痕，删了也能从历史里翻出来
- 你的 key 可能被推到公开仓库 → 别人拿去刷你的额度
- 换 key 要改代码、重新部署；环境变量改一下就行

所以：**秘密从环境变量读，代码里只出现变量名**。

### 4.2 为什么自己写 15 行 .env 解析，而不是装 `python-dotenv`

参考版就是自己写的，原因有三个：

1. 少一个依赖 → 少一次 `pip install` 失败的风险（这在教学项目里很重要）
2. 这 15 行你看得懂每一行，出问题能自己修；装个包就变成黑盒
3. `.env` 格式简单到不值得引一个库

> 真实项目里用 `python-dotenv` 完全可以，甚至更好（支持多行值、变量展开）。但**先手写过一遍，你才知道那个库替你做了什么。**

### 4.3 为什么用 `setdefault` 而不是直接赋值

```python
os.environ.setdefault(key, value)   # 已有值就不动
```

因为优先级是：**真实环境变量 > .env 文件**。

部署时（服务器、CI）是用环境变量注入 key 的，`.env` 只是本地开发的方便。如果 `.env` 覆盖真实环境变量，就会出现"线上明明配了 key，却用了 .env 里的旧 key"这种鬼事。

### 4.4 为什么 `PROVIDERS` 是一张表，不是一长串 `if/elif`

```python
PROVIDERS = {"deepseek": {...}, "fake": {...}}
```

- 加一家厂商 = 加一行字典，不用碰任何逻辑
- `if provider == "deepseek": ... elif provider == "qwen": ...` 会越写越长，而且每个分支里都是重复代码
- 还能顺手做校验：`if provider not in PROVIDERS: 报错，并把可选值列出来`

> 这就是"数据驱动"的最小形态：**能放进表里的东西，不要写进 if。**

### 4.5 为什么要有 `Config` 这个 dataclass

不用它的话，`create_client(provider, api_key, base_url, model)` 每次都得传 4 个参数，而且顺序传错了不报错。

用 `Config` 之后：
- 传一个对象，字段名写错 `PyCharm` 当场标红
- 以后加字段（比如 `timeout`）只改 `Config`，调用点不用动
- 测试里可以 `Config("fake", "", "", "fake")` 一行造出来

### 4.6 为什么 `load_config` 里要 `env_file or Path(".env")`

给测试留一个口子：测试传自己的临时 `.env`，就不受你项目里 `.env` 的影响。

这和阶段 1 的 `today` 参数、`TaskStore(path)` 是**同一个思路**：把"从哪读"变成参数，而不是写死在函数里。这个名字叫**依赖注入**。

### 4.7 为什么 `create_client` 里 `import openai` 要写在函数内部

```python
def create_client(cfg):
    if cfg.provider == "fake":
        return FakeClient()
    ...
    from openai import OpenAI    # ← 延迟导入
```

写在文件顶部的话，**没装 openai 的人连 fake 模式都跑不了**（一 import 就 ImportError）。

延迟导入后：离线模式零依赖，装不装 openai 都能跑。这叫**延迟导入**，代价是每次调用都查一次 import 缓存（可以忽略）。

### 4.8 为什么"没有 Key"要报一句这么长的话

```python
raise RuntimeError(
    "没有找到 API Key。请在项目根目录创建 .env 文件，写入：\n"
    "  STUDYMATE_PROVIDER=deepseek\n"
    "  STUDYMATE_API_KEY=你的key\n"
    "或者先用 STUDYMATE_PROVIDER=fake 离线体验。"
)
```

因为"没配 key"是**每个新手第一次跑必踩**的坑。报错信息直接告诉他怎么修，他就不用去搜。

对比一下失败版本：`raise RuntimeError("no key")` —— 用户看到只会想"什么 key？放哪？"

> **报错信息是产品的一部分。** 你写的是给人看的，不是给编译器看的。

### 4.9 为什么 FakeClient 要"长得和真 SDK 一样"

真 SDK 的调用长这样：

```python
resp = client.chat.completions.create(model=..., messages=[...])
text = resp.choices[0].message.content
```

假客户端也必须长这样，**否则上层代码就得为"离线/在线"写两套**：

```python
if fake:
    text = client.get_fake_reply()
else:
    text = client.chat.completions.create(...).choices[0].message.content
```

这种分叉一旦出现，测试走的路径和线上路径就不一样了——**测过的东西上线照样炸**。

所以 FakeClient 用 `SimpleNamespace` 捏出同样的形状：`.chat.completions.create(...)`、`.choices[0].message.content`。上层代码一行不改，fake 和真实无缝切换。

> 这就是"面向接口编程"的最小形态：测试替身只要形状一致，行为可以完全不同。

### 4.10 为什么要把 `messages` 和 `script` 复制一份

```python
self._owner.calls.append({..., "messages": [dict(m) for m in messages]})
self.script = list(script) if script is not None else None
```

两个都是**同一个病**：不复制，你就在和调用方共享同一个对象。

- 不复制 `messages`：调用方后面改了会话历史（agent 里很常见），你记录的"当时发了什么"跟着变，测试就没法信了
- 不复制 `script`：你 `pop` 的时候会把调用方的列表吃空，第二次用同一个列表就空了

这和阶段 1 `TaskStore.__init__` 里 `list(tasks or [])` 是**完全同一课**：
**收下别人的可变对象，要么复制，要么别改它。**

`dict(m)` 是浅拷贝——只复制这一层字典。对 `{"role": ..., "content": ...}` 这种扁平结构足够；如果 content 里嵌了列表，就得 `copy.deepcopy`。

### 4.11 为什么用"剧本"而不是"假装智能"

`FakeClient(script=["第一句", "第二句"])` —— 每次调用依次吐一句。

- **可控**：测试想要什么回复就写什么，不用猜
- **可复现**：同样的剧本永远同样的结果，不会今天过明天挂
- **能测边界**：剧本演完了会怎样？正好写一条测试

参考版还多了一个 `_rule_based`（按关键词路由到工具），那是为了让人能手动玩 agent。阶段 3 再写。

### 4.12 为什么 provider 默认是 `fake`

```python
provider = os.getenv("STUDYMATE_PROVIDER", "fake")
```

新人把项目 clone 下来，直接 `python phase2.py` 就能看到输出，**不用先注册账号、拿 key、配 .env**。

第一次跑通的门槛越低，越有可能真的跑起来。

## 五、四个坑

1. **`os.environ.setdefault` 写成 `os.environ[key] = value`** → 覆盖了真实环境变量，违反"环境变量优先"的规矩（`test_does_not_override_existing_env` 专抓）
2. **记录 `messages` 时忘了 `dict(m)`** → 存的是同一批字典，调用方一改就污染（`test_messages_are_copied`）
3. **`self.script = script` 忘了 `list(...)`** → `pop` 会吃掉调用方的列表（`test_script_list_is_copied`）
4. **`os.getenv` 和 `os.environ` 混用** → `os.environ["不存在的键"]` 抛 `KeyError`，`os.getenv` 返回默认值。读可选配置一律用 `os.getenv`

## 六、C 程序员对照表

| Python | C 里对应什么 | 差别 |
|---|---|---|
| `os.getenv("X", 默认)` | `getenv("X")` + 判 NULL | Python 可以直接给默认值 |
| `@dataclass` | `struct` | 自动生成构造/打印/相等 |
| `SimpleNamespace` | 匿名 `struct` / 临时拼的结构体 | 不用先定义类型就能用 `.x` 取值 |
| `[dict(m) for m in messages]` | 手写 `malloc` + `memcpy` | Python 帮你分配，但同样要小心"深/浅" |
| `raise RuntimeError(...)` | `fprintf(stderr, ...); return -1;` | 抛异常不会被忽略 |
| 延迟导入 | 运行时 `dlopen` | 用不到就不加载 |

# 阶段 2 结构总览：配置 + 模型客户端

> 这张图回答三个问题：**有哪些东西？谁调用谁？为什么需要它？**
> 代码在 `phase2.py`，验收在 `test_phase2.py`（21 个测试），设计理由在 `说明_为什么.md`。

## 一、一眼看全

```
入口：main.py / 测试
   │
   ├─ load_config(env_file) ─────────────────────────────────┐
   │        │                                                │
   │        ├─► load_dotenv(path) ──► os.environ（进程环境变量）│
   │        │        （.env 文件里的 KEY=VALUE 写进去）        │
   │        │                                                │
   │        ├─► PROVIDERS[provider]  ← 预设表（网址 + 模型名）  │
   │        │                                                │
   │        └─► Config(4 个字段)   ← @dataclass 生成 __init__  │
   │                                                         │
   └─ create_client(cfg) ◄───────────────────────────────────┘
            │
            ├─ provider == "fake" ─► FakeClient()
            │                          │
            │                          ├─ self.script  剧本（list[str]）
            │                          ├─ self.calls   每次请求的记录
            │                          └─ self.chat = SimpleNamespace(completions=_Completions(self))
            │                                   │
            │                                   ▼
            │                          _Completions.create(model, messages)
            │                                   ├─ calls.append({model, messages 的副本})
            │                                   └─ _next()
            │                                          ├─ 剧本空 → RuntimeError
            │                                          └─ _response(剧本.pop(0))
            │                                                   │
            │                                                   ▼
            │                                   resp.choices[0].message.content
            │
            └─ 其他 ─► OpenAI(api_key, base_url)   ← 延迟 import（fake 模式不用装 openai）
                              │
                              └─ 真 SDK，同样有 .chat.completions.create(...)
```

**一句话**：`load_config` 负责"配置从哪来"，`create_client` 负责"选哪套后端"，`FakeClient` 负责"离线也能跑"。

## 二、文件头：import 了什么，为什么

| 写法 | 导入的东西 | 干什么 | 谁在用 | 不导入会怎样 |
|---|---|---|---|---|
| `from __future__ import annotations` | （编译开关） | 类型注解延迟成字符串 | 全文件 | 旧版 Python 写 `list[str]` 会报错 |
| `import os` | `os` 模块 | `os.environ` 读写环境变量、`os.getenv` 带默认值 | `load_dotenv` / `load_config` | `NameError` |
| `from dataclasses import dataclass` | `dataclass` | 把 `Config` 变成自动生成 `__init__` 的类 | `Config` | 要手写 `__init__(self, ...)` 8 行 |
| `from pathlib import Path` | `Path` | 路径对象（`.exists()` / `.read_text()`） | `load_dotenv` 的参数类型 | 只能传字符串 |
| `from types import SimpleNamespace` | `SimpleNamespace` | 临时捏一个"有属性"的对象，模仿 SDK 返回结构 | `_response` / `FakeClient.__init__` | 要用 class 手写一个返回类型，啰嗦 |
| `from openai import OpenAI`（**函数内部**） | 真 SDK | 真联网时创建客户端 | `create_client` 的非 fake 分支 | fake 模式也要求装 openai；不装就 ImportError |

**为什么 `openai` 写在函数内部**：延迟导入。离线模式（provider=fake）根本不需要它，写在文件顶部会让"没装 openai 的人连测试都跑不了"。

## 三、装饰器：只有 `@dataclass` 一个

| 装饰器 | 作用在 | 它替你生成了什么 | 不用会怎样 |
|---|---|---|---|
| `@dataclass` | `class Config` | `__init__(self, provider, api_key, base_url, model)` + `__repr__` + `__eq__` | 要手写赋值；测试里 `Config(...) == Config(...)` 会是 `False` |

> 这就是"Config 里为什么没有 self"的答案：`self` 在生成的 `__init__` 里，不在类体里。

## 四、五个模块级部件

| 名字 | 类型 | 干什么 | 谁调用它 |
|---|---|---|---|
| `PROVIDERS` | 常量 dict | 厂商预设表：名字 → {base_url, model} | `load_config` 查表 |
| `load_dotenv(path)` | 函数 | 把 `.env` 的 KEY=VALUE 写进 `os.environ`（不覆盖已有值） | `load_config` |
| `Config` | `@dataclass` | 一次请求需要的 4 个字段打包 | `load_config` 产出、`create_client` 消费 |
| `load_config(env_file)` | 函数 | 读环境变量 + 查预设表 → `Config` | `main.py`、测试 |
| `create_client(cfg)` | 函数 | 按 provider 返回能发请求的对象 | `main.py` |
| `_response(content)` | 函数 | 用 `SimpleNamespace` 捏出 `.choices[0].message.content` 的形状 | `_next` |

## 五、两个类（假 SDK）

| 类 | 方法 | 干什么 | 备注 |
|---|---|---|---|
| `_Completions` | `__init__(owner)` | 记下"我是哪个 FakeClient 的零件" | 下划线开头 = 内部零件 |
| | `create(model, messages, **kwargs)` | ① 把请求记进 `owner.calls`（messages 要复制）② 返回 `owner._next()` | `**kwargs` 兜住真 SDK 的几十个可选参数 |
| `FakeClient` | `__init__(script=None)` | 建 `script`（要 `list(...)` 复制）、`calls=[]`、`chat=SimpleNamespace(completions=_Completions(self))` | 把"三层结构"拼出来 |
| | `_next()` | 剧本空/没给 → `RuntimeError`；否则 `pop(0)` 并包成响应 | 保证剧本按顺序播一次 |

**为什么要有 `_Completions` 这个中间类**：真 SDK 的调用层级是

```
client.chat.completions.create(...)
  对象   属性   属性        方法
```

假货必须复制这个层级，否则上层代码要写成 `client.create(...)`，和真 SDK 不一致 → 离线/在线两套代码。

## 六、数据流

```
.env 文件 ──load_dotenv──► os.environ
                              │
环境变量 ────os.getenv───────► │
                              ▼
                     provider / api_key
                              │
                     PROVIDERS[provider]（预设 base_url/model）
                              │
                              ▼
                        Config(4 字段)
                              │
                       create_client(cfg)
                        ┌─────┴─────┐
                   fake │           │ 其他
                        ▼           ▼
                   FakeClient()   OpenAI(...)   ← 延迟 import
                        │           │
                        └─────┬─────┘
                              ▼
        client.chat.completions.create(model=..., messages=[...])
                              │
                              ▼
                 resp.choices[0].message.content
```

## 七、为什么这样分层（四条）

1. **配置和客户端分开**：`Config` 只是数据（4 个字符串），`create_client` 才做"选后端"的决定。加一个厂商只改 `PROVIDERS` 表。
2. **秘密不进代码**：key 只从环境变量/`.env` 读，代码里只有变量名。`.`gitignore` 要忽略 `.env`。
3. **假货必须同形**：`FakeClient` 复制真 SDK 的调用形状和返回形状，上层代码一行不用改就能在离线/在线之间切换。
4. **延迟导入**：`openai` 只在真需要时导入，离线模式零第三方依赖。

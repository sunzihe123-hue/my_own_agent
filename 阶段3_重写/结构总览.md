# 阶段 3 结构总览：工具注册表 + agent 循环

> 这张图回答三个问题：**有哪些东西？谁调用谁？为什么需要它？**
> 代码在 `tools.py` + `agent.py`，验收在 `test_tools.py`（15 条）+ `test_agent.py`（13 条），设计理由在 `说明_为什么.md`。

## 一、一眼看全

```
入口：main.py / 测试
   │
   ├─ ToolRegistry()                     ← 注册表：名字 → Tool
   │     │
   │     ├─ @reg.tool("描述", params={...})   ← 装饰器：读函数签名，自动登记
   │     │       │
   │     │       └─ inspect.signature + typing.get_type_hints
   │     │              ↓
   │     │        Tool(name, description, func, parameters)
   │     │
   │     ├─ reg.schemas() → [ {...JSON Schema...} ]   ← 发给模型的工具清单
   │     │
   │     └─ reg.execute(name, arguments_json) → str   ← 真的执行，错误也变成字符串
   │
   └─ Agent(client, model, registry, max_steps)
         │
         ├─ self.messages = [ {"role": "system", "content": 提示词} , ... ]
         │
         └─ chat(user_text) ────────────────────────┐
                │                                    │
                ├─ messages.append(user)             │
                │                                    │
                └─ for step in range(max_steps):     │
                       │                             │
                       ├─ _call_model() ──► client.chat.completions.create(
                       │                        messages=self.messages,
                       │                        tools=self.registry.schemas() or None)
                       │       │
                       │       ▼
                       │    resp.choices[0].message
                       │       │
                       │       ├─ 没有 tool_calls → 这就是答案，return
                       │       │
                       │       └─ 有 tool_calls：
                       │             ① assistant 消息（含 tool_calls）记进历史
                       │             ② 逐个 registry.execute(name, arguments)
                       │                结果作为 role="tool" + tool_call_id 记进历史
                       └──────── 回到循环开头（模型看着工具结果继续）
```

**一句话**：`ToolRegistry` 负责"有哪些本事"，`Agent` 负责"什么时候用、用完怎么接着想"。

## 二、文件头：import 了什么，为什么

| 文件 | 写法 | 导入的东西 | 干什么 | 不导入会怎样 |
|---|---|---|---|---|
| `tools.py` | `from __future__ import annotations` | （编译开关） | 注解延迟成字符串，可写 `list[dict]` / `str | None` | 旧版 Python 语法报错 |
| | `import inspect` | 反射工具 | `inspect.signature` 读参数名和默认值 | 只能靠人肉手写 schema |
| | `import json` | JSON 编解码 | `json.loads` 解析参数、`json.dumps` 序列化结果 | 模型给的参数是字符串，没法变成 dict |
| | `import types` / `import typing` | 类型工具 | `get_origin` / `get_args` 处理 `str | None`、`list[...]` | 可空参数的类型映射会错 |
| | `from dataclasses import dataclass, field` | 数据类 | `Tool` / `ToolRegistry` 自动生成 `__init__` | 每个类手写 `__init__` |
| | `from typing import Any, Callable` | 类型标注 | 只是标签，运行时不起作用 | 无（可读性差一点） |
| `agent.py` | `from datetime import date` | 日期 | 把今天日期填进 system prompt | 提示词里 `{today}` 没法替换 |
| | `from tools import ToolRegistry` | 本阶段模块 | 类型标注 + 调 `schemas()` / `execute()` | agent 不知道工具有哪些 |

## 三、部件表

### tools.py

| 名字 | 类型 | 干什么 | 谁调用它 |
|---|---|---|---|
| `_json_type(annotation)` | 函数（已给） | Python 类型 → JSON Schema 类型名 | `tool()` |
| `Tool` | `@dataclass` | 一个工具的全部信息 | `ToolRegistry` |
| `Tool.schema()` | 方法 | 拼成 OpenAI 要的 `{"type": "function", ...}` | `schemas()` |
| `ToolRegistry` | `@dataclass` | 工具表：`tools: dict[str, Tool]` | 使用者 |
| `ToolRegistry.tool()` | 方法（返回装饰器） | 登记被装饰的函数 | `@reg.tool(...)` |
| `ToolRegistry.schemas()` | 方法 | 所有工具的描述列表 | `Agent._call_model()` |
| `ToolRegistry.execute()` | 方法 | 执行工具，**永远返回字符串** | `Agent.chat()` |

### agent.py

| 名字 | 类型 | 干什么 | 备注 |
|---|---|---|---|
| `DEFAULT_SYSTEM_PROMPT` | 常量 | 给模型的角色和规则 | 含 `{today}` 占位符 |
| `Agent.__init__` | 方法 | 存 client / model / registry / max_steps，初始化 `messages` | 第一条是 system |
| `Agent.chat(user_text)` | 方法 | **核心循环**：调模型 → 有工具就执行 → 再调 | 返回最终文本 |
| `Agent._call_model()` | 方法 | 发一次请求，返回 `resp.choices[0].message` | `tools=... or None` |

## 四、数据流：一次"带工具调用"的 chat，messages 怎么长

```
初始：       [system]
chat("2+3=?")： + user("2+3=?")                     → 第 1 次请求
模型回复：    content=None, tool_calls=[call_1: add({"a":2,"b":3})]
             + assistant(tool_calls=[...])            ← 必须原样记
执行工具：    add(2,3) → 5
             + tool(tool_call_id="call_1", content="5")
                                                     → 第 2 次请求
模型回复：    content="2+3=5", tool_calls=None
             + assistant("2+3=5")  → return
```

关键点：**每轮都把整个 `messages` 发过去**（接口无状态），所以历史就是模型的"记忆"；工具结果靠 `tool_call_id` 与请求配对。

## 六、这一步的三条设计取舍

1. **schema 自动生成**：函数签名是唯一事实来源，避免"签名改了、schema 没改"
2. **错误变字符串**：模型是调用方，它需要能读懂、能改正；抛异常等于对话终止
3. **循环 + 上限**：多轮工具调用是 agent 的本质；`max_steps` 是防死循环的安全带

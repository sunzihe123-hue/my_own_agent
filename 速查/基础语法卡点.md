**看懂这份文档的方法**：每一条都问同一个问题——**"这段代码等价于我手写的什么？"**

只要答得出"等价写法"，那些"看起来少写了东西"的地方就不再神秘：一定有一个装饰器、一个协议、或者一个默认行为替你写了。

## 1. `Config` 里为什么没有 `self`？—— `@dataclass` 生成了 `__init__`

**你看到的：**

```python
@dataclass
class Config:
    provider: str
    api_key: str
    base_url: str
    model: str
```

**等价于手写：**

```python
class Config:
    def __init__(self, provider, api_key, base_url, model):
        self.provider = provider
        self.api_key = api_key
        self.base_url = base_url
        self.model = model
```

**为什么：** 类体里那 4 行是"字段声明"，`@dataclass` 读它们，生成 `__init__`。
`self` 永远只出现在**方法的参数列表**里，类体里没有它的位置。

```python
>>> import inspect
>>> inspect.signature(Config.__init__)
<Signature (self, provider: str, api_key: str, base_url: str, model: str) -> None>
>>> Config("fake", "", "", "fake").__dict__
{'provider': 'fake', 'api_key': '', 'base_url': '', 'model': 'fake'}
```

## 2. `self` 到底是什么？—— 只是一个参数名，不是关键字

```python
>>> from phase2 import Config
>>> c = Config("fake", "", "", "fake")
>>> Config.__dict__["provider"]        # 类上只有默认值，没有实例数据
AttributeError: 'mappingproxy' object has no attribute 'provider'
>>> c.__dict__["provider"]             # 实例的数据在 __dict__ 里
'fake'
```

`self` 可以改名（虽然约定都叫 self）：

```python
class A:
    def hello(this):      # 叫 this 也能跑！
        return "hi"

>>> A().hello()
'hi'
>>> A.hello(A())          # 等价的显式写法：t.method(t) == T.method(t)
'hi'
```

**记住这一条就够：`obj.method(x)` 等价于 `Class.method(obj, x)`。** 第一个参数就是那个对象本身，只是 `obj.method(x)` 这种写法把它自动传进去了。

> 阶段 1 的 `t.describe()` 和 `Task.describe(t)` 完全等价——这就是为什么方法定义里必须写 `self`。

## 3. `@dataclass` 还偷偷生成了什么？—— `__repr__` 和 `__eq__`

阶段 1 的测试里为什么能写 `self.assertEqual(Config(...), Config(...))`？因为你没写 `__eq__`，但 dataclass 生成了。

```python
>>> Config("fake", "", "", "fake") == Config("fake", "", "", "fake")
True
>>> print(Config("fake", "", "", "fake"))
Config(provider='fake', api_key='', base_url='', model='fake')
```

手写的话要 10 行。类比 C：`struct` 不会自动给你 `printf` 和 `==`，Python 的 dataclass 会。

**自己试：** 把 `@dataclass` 删掉，这两个行为立刻消失（`print` 变成 `<Config object at 0x...>`，`==` 变成 `False`）。

## 4. `@staticmethod` / `@classmethod`：什么时候**不需要** `self`

```python
class Factory:
    @staticmethod
    def make():              # 不碰实例，也不需要类
        return "做出来了"

    @classmethod
    def build(cls):          # 拿到类本身（不是实例）
        return cls()

>>> Factory.make()           # 不用实例就能调
'做出来了'
>>> Factory.build()
<__main__.Factory object at ...>
```

**判断法**：方法体里用到 `self.xxx` 吗？用 → 普通方法；不用但要造实例 → `@classmethod`；俩都不用 → `@staticmethod`。

> 阶段 2 的 `load_dotenv`、`load_config` 都是**模块级函数**，不属于任何类，所以从头到尾没有 `self`。不是所有东西都该塞进类里。

## 5. 类属性 vs 实例属性：默认值被共享的坑

```python
class Counter:
    hits = 0                 # 类属性：所有实例共享

    def bump(self):
        self.hits += 1       # 注意：这会创建"实例属性"，不再改类属性

>>> a, b = Counter(), Counter()
>>> a.bump(); a.hits, b.hits
(1, 0)
```

对比阶段 1 的 `TaskStore`：

```python
def __init__(self, tasks=None):
    self.tasks = list(tasks or [])   # 实例属性：每个对象一份
```

**坑**：`def add(self, item, bucket=[])` 这种**可变默认值**会被所有调用共享——这和 `field(default_factory=...)` 要解决的问题是同一个（见第 6 条）。

## 6. `field(default_factory=...)`：默认值"什么时候"求值

```python
@dataclass
class Task:
    created_at: str = field(default_factory=_now)   # ✅ 每次 new 都调一次
    # created_at: str = _now()                      # ❌ 类定义时调一次，全体共享
```

等价的手写：

```python
class Task:
    def __init__(self):
        self.created_at = _now()      # 每次实例化都会执行
```

**为什么 `= _now()` 是错的**：类体在**定义时**执行一次，`_now()` 立刻被调用，结果被当成"默认值常量"，所有实例拿到同一个时间戳。

```python
>>> from datetime import datetime
>>> class A: t = datetime.now()        # 定义时求值
>>> import time; time.sleep(1)
>>> A().t == A().t
True      # ❌ 两个"不同时刻创建"的任务时间戳一样
```

> `default_factory` 收的是**函数本身**，等实例化时才调用。这和 C 里"函数指针"与"函数返回值"的区别是一回事。

## 7. `@property`：方法不加括号就能访问

```python
class Task:
    def __init__(self):
        self._done = False

    @property
    def done(self):           # 看起来像属性，其实是方法
        return self._done

>>> Task().done               # 没有括号！
False
```

**为什么有用**：外部写法是 `task.done`（像字段），但内部可以加计算逻辑；以后想把字段换成计算方法，调用方一行都不用改。

> 阶段 1 的 `describe()` 是普通方法，因为它"真的要做一件事"（拼字符串）；如果它只是读一个值，就该是 `@property`。

## 8. `__len__` / `__iter__`：为什么 `len(store)` 和 `for t in store` 能用

```python
class TaskStore:
    def __len__(self):
        return len(self.tasks)

>>> len(store)          # 等价于 store.__len__()
3
```

`len()`、`for`、`==`、`print()`、`with` 这些**内置操作**，Python 都会去对象上找对应的双下划线方法（叫"魔法方法"或"协议"）：

| 你写的 | Python 实际调用 |
|---|---|
| `len(x)` | `x.__len__()` |
| `for i in x` | `x.__iter__()` |
| `x == y` | `x.__eq__(y)` |
| `print(x)` | `x.__repr__()` |
| `with x:` | `x.__enter__()` / `x.__exit__()` |
| `x[0]` | `x.__getitem__(0)` |

**看懂这张表，`__init__` 也就通了**：`Config(...)` 等价于 `Config.__init__(新对象, ...)`。

## 9. `with open(...)`：谁在替你 `close`

```python
with open("a.txt", encoding="utf-8") as f:
    text = f.read()
# 离开缩进，文件自动关闭（即使中间抛异常）
```

等价于：

```python
f = open("a.txt", encoding="utf-8")
try:
    text = f.read()
finally:
    f.close()
```

**为什么能自动**：文件对象实现了 `__enter__` / `__exit__`。`with` 就是"进入时调 `__enter__`，离开（不管正常还是异常）调 `__exit__`"。

> C 里 `fopen` 之后忘了 `fclose` 会泄漏句柄；Python 的 `with` 是逼你写在作用域里的安全写法。

## 10. `if __name__ == "__main__":`：一个文件的两副身份

```python
if __name__ == "__main__":
    print("被直接运行")
```

- **直接运行** `python phase2.py` → `__name__` 等于 `"__main__"` → 里面的代码执行
- **被别人 import** `import phase2` → `__name__` 等于 `"phase2"` → 里面的代码不执行

```python
>>> import phase2          # 不会打印任何自测输出
>>> phase2.__name__
'phase2'
```

**为什么需要**：同一个文件既能当"脚本跑一遍看效果"，又能当"模块被测试导入"，两不冲突。这就是为什么测试 import 你的 `phase2.py` 时，那个自测 demo 不会乱跑。

## 11. `Task(**d)`：`**` 是"把字典拆成关键字参数"

```python
def f(a, b):
    return a + b

>>> d = {"a": 1, "b": 2}
>>> f(**d)          # 等价于 f(a=1, b=2)
3
```

阶段 1 的 `_load` 里 `[Task(**d) for d in data]` 就是这个意思：JSON 读回来是一堆字典，`**` 把 `{"id": 1, "title": "x"}` 变成 `Task(id=1, title="x")`。

**注意**：键名必须和参数名逐字相同，否则 `TypeError: unexpected keyword argument`。

## 12. `*args` / `**kwargs`：为什么 `create(..., **kwargs)` 能接任意参数

```python
def create(self, model, messages, **kwargs):
    # kwargs 是"剩下所有关键字参数"的字典
    print(kwargs)

>>> create("m", [], temperature=0.7, max_tokens=10)
{'temperature': 0.7, 'max_tokens': 10}
```

真 SDK 的 `create` 有几十个可选参数，签名里一个个列太累，就用 `**kwargs` 兜住。
**代价**：参数名打错不会报错，会静静地进 `kwargs` 然后被忽略——这是 Python 里很常见的一类"无声 bug"。

## 13. 类型注解只是"标签"，运行时不检查

```python
def add(a: int, b: int) -> int:
    return a + b

>>> add("1", "2")        # 传字符串也不报错！
'12'
```

`int` 只是给**人**和**IDE**（PyCharm 的标红、补全）看的，Python 运行时不会拦你。

`from __future__ import annotations` 的作用：让注解**以字符串形式**保存，这样能写 `list[Task]`、`str | None` 而不用先定义 `Task`（也避免了循环导入）。

```python
>>> Task.__annotations__
{'id': 'int', 'title': 'str', ...}   # 注意是字符串
```

> 类型不检查，**所以要写测试**——这是阶段 4 讲单元测试的伏笔。

## 14. 下划线 `_` 的约定：不是语法，是规矩

| 写法 | 含义 | 实际效果 |
|---|---|---|
| `_response` | 模块内部使用 | **没有强制力**，外部照样能 import |
| `self._owner` | 实例内部属性 | 同上，只是"请别碰" |
| `__init__` / `__len__` | 双下划线 = Python 协议 | 有强制力（`len()` 会找它） |
| `__dict__` 之类 | 同上 | 同上 |

**两个下划线结尾的才是"协议"**（Python 会调用），一个下划线开头只是"约定"（人看）。

# 把这个学习法装进各种 AI：安装说明

## 先搞清楚"skill"到底是什么

不是一个神秘插件，就是一个**文件夹 + 一个 `SKILL.md`**：

```
reference-driven-practice/
└── SKILL.md        ← 开头是 YAML 头，正文是给 AI 的指令
```

`SKILL.md` 开头的两行最关键：

```yaml
---
name: reference-driven-practice
description: 用"参考实现→骨架→验收测试→红绿循环→收尾审查"的方式带用户重写模块。当用户说"我要学X""照着这份代码练""给我出个练习"时使用。
---
```

- `name` 是标识，只能用英文小写和连字符
- **`description` 决定"什么时候自动触发"** —— 写给 AI 看的触发条件，不是写给人看的介绍。这里写得好不好，直接决定你在新对话里它会不会自己跳出来
- 正文（`---` 之后）才是真正的指令，长度控制在 1~2 屏以内，太长会被截断或拖慢响应

## 三个层次，按你的场景选

| 方式 | 适用 | 通用性 | 自动化 |
|---|---|---|---|
| A. 粘贴精简提示词 | 所有 AI（含网页版） | ★★★ | 手动 |
| B. `SKILL.md` 文件夹 | Claude 系、支持 skills 的平台 | ★★ | 自动 |
| C. 平台原生产品功能 | 各平台自己的"自定义指令/智能体" | ★ | 自动 |

**建议：先做 A（5 分钟，立刻能用），再挑常用的平台做 B 或 C。**

---

## A. 精简提示词（最快、最通用）

打开 `精简提示词.md`，把 `---` 之间的那段整段复制，粘到对应位置：

| 平台 | 位置 | 备注 |
|---|---|---|
| ChatGPT | 设置 → 个性化 → 自定义指令 | 两栏各 1500 字符上限，粘一栏就够 |
| ChatGPT Custom GPT | 新建 GPT → 配置 → 指令 | 8000 字符，可以放完整版 |
| ChatGPT 项目 | 项目设置里的指令 | 只在该项目生效 |
| Gemini | Gems → 新建 Gem → 指令 | 起名"编程教练" |
| Claude 网页版 | 设置 → 个性化/自定义指令；或 Project 的指令 | 也可用 B 方式 |
| 豆包 / 通义 / Kimi 等 | 新建智能体 / 角色设定 / 对话首条 | 界面名称各家不同，找"角色""人设""指令" |
| 任何 AI | 对话第一条消息直接粘 | 零配置，最保险 |

> 这些界面位置会随版本变。找不到就搜关键词：`自定义指令`、`Custom Instructions`、`系统提示`、`System prompt`、`智能体`。

## B. SKILL.md 文件夹（支持 skills 的平台）

本目录里已经有一个可直接用的 `reference-driven-practice/` 文件夹。

**Claude 网页版 / 桌面版**
设置 → 能力（Capabilities）→ Skills → 上传，选 `reference-driven-practice.zip`。

**Claude Code**
把 `reference-driven-practice/` 整个文件夹放到：
- 个人级：`~/.claude/skills/`（对你所有项目生效）
- 项目级：`<项目根>/.claude/skills/`（只对这个项目生效）

放好后新开一个会话，用一句话验证（见下面"自检"）。

**其他支持 skills 的 IDE / Agent 工具**
格式基本一致（文件夹 + `SKILL.md` + YAML 头），放到它文档里写的 skills 目录。先查该工具的文档关键词：`skills directory`、`agent skills`。

## C. 平台原生产品功能

- **Cursor**：项目根建 `.cursor/rules/learning.mdc`，把精简提示词粘进去，前面加一行 `alwaysApply: true` 的 frontmatter
- **GitHub Copilot**：项目根 `.github/copilot-instructions.md`
- **VSCode + Cline / Roo 等**：各自的"自定义规则"文件
- **本工具（DeepSeek Harness）**：skill 是内置打包的，本机看不到可写的 skills 目录。最省事的办法是：把精简提示词作为**会话第一条消息**，或直接说"按我的学习法来"，并把 `学习方法.md` 一起放进项目让它读

## 自检（装完必须做，30 秒）

新开一个对话，只发这一句：

```
我要学写一个日志解析模块，参考实现在 logs/parser.py
```

| 反应 | 判定 |
|---|---|
| 先看文件/报行数，划出最小版本和部件清单，然后给骨架，不给实现 | ✅ 生效 |
| 直接贴一坨能跑的代码 | ❌ 没生效 |
| 开始讲日志解析的原理 | ❌ 没生效（被平台默认人格覆盖了） |

没生效的常见原因：没点保存 / 粘到了"知识库"而不是"指令" / 提示词被平台自带人格压过（在开头加一句"以下规则优先级最高，覆盖你的默认风格"）。

## 维护建议

1. **一个 skill 只干一件事**。学习法、代码审查、文档写作，各自一个文件夹，别混。
2. **`description` 反复改**。它是触发开关，比正文更重要。发现"该触发时没触发"，先改它。
3. **正文别超过 2 屏**。超了就拆成第二个 skill，或者把细节挪进同目录的参考文件（skill 正文只留"什么时候读哪个文件"）。
4. **留版本号**：文件末尾写 `v1.0 / 2026-11-04`。改到第 3 版你会发现不记版本根本不知道哪版好用。
5. **每次踩坑补一条"禁止"**。规则里的负面清单是最有效的部分——AI 最容易犯的错就那几种，写死它。

## 一、一眼看全

```
用户 / 测试 / __main__ 自测
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ TaskStore            管"一批任务"（内存 + 磁盘）           │
│   __init__(path)  ──► _load()      读文件 → self.tasks     │
│   add/complete/delete ──► _save()  改完立刻写回文件        │
│   get/list/upcoming   只读 self.tasks，不碰磁盘            │
└────────────────────────┬─────────────────────────────────┘
                         │ 操作的是（一对多）
                         ▼
┌──────────────────────────────────────────────────────────┐
│ Task  (@dataclass)    管"一条任务"                         │
│   字段：id title due course done created_at                │
│   方法：days_left()  还剩几天                              │
│         describe()   一行人类可读文本                      │
└────────────────────────┬─────────────────────────────────┘
                         │ 依赖
                         ▼
┌──────────────────────────────────────────────────────────┐
│ 模块级工具（不属于任何类）                                  │
│   parse_due()   校验 + 归一化 "20261020" → "2026-10-20"    │
│   _now()        生成创建时间字符串                          │
│   TaskError / TaskNotFoundError   错误分类                  │
└──────────────────────────────────────────────────────────┘
```

**三层职责一句话**：TaskStore 管"存和找"，Task 管"自己长什么样"，工具函数管"单个值的校验和时间"。

## 二、文件头：import 了什么，为什么

> C 程序员的类比：Python 的 `import` ≈ `#include` + 链接。区别是 Python 不需要"先声明"，用到名字就去对应模块里找。

| 写法 | 导入的东西 | 干什么 | 谁在用 | 不导入会怎样 |
|---|---|---|---|---|
| `from __future__ import annotations` | （编译开关，不是模块） | 让类型注解延迟成字符串 | 全文件 | 旧版 Python 里 `list[Task]` 会报错；3.13 其实可省，留着是习惯 |
| `import json` | `json` 模块 | `json.loads` 解析、`json.dumps` 生成 | `_load` / `_save` | `NameError: json is not defined` |
| `from dataclasses import asdict, dataclass, field` | 3 个工具 | `@dataclass` 装饰器、`asdict` 转字典、`field` 配默认工厂 | `Task` / `_save` | `NameError: dataclass is not defined` |
| `from datetime import date, datetime, timedelta` | 3 个类型 | `date` 校验日期、`datetime` 取当前时间、`timedelta` 算 days 后 | `parse_due` / `_now` / `days_left` / `upcoming` | 同上 |
| `from pathlib import Path` | `Path` | 路径对象，`.exists()` `.read_text()` `.replace()` | `TaskStore` | 只能退回字符串拼路径 + `os.path` |
| `import tempfile`（在 `__main__` 里） | `tempfile` | 自测时造临时目录 | `if __name__ == "__main__"` | 自测会往项目目录写垃圾文件 |

**为什么 `tempfile` 写在 `__main__` 里面**：只有"自测"才需要它，正常被 import 时不该执行——这叫延迟导入，和阶段 2 的 `import openai` 同一个道理。

## 三、装饰器：只有 `@dataclass` 一个

| 装饰器 | 作用在 | 它替你生成了什么 | 不用会怎样 |
|---|---|---|---|
| `@dataclass` | `class Task` | `__init__`（6 个字段赋值）、`__repr__`（print 能看）、`__eq__`（能直接 `==`） | 要手写约 15 行；`print(task)` 只显示 `<Task object at 0x...>` |
| `field(default_factory=_now)` | `created_at` 字段 | （不是装饰器）声明"默认值用函数现算，不是常量" | 写成 `= _now()` 会让所有任务共享同一个创建时间 |

**注意 `@dataclass` 的顺序**：必须先 `import` 才能用；它只处理"字段声明"，不处理方法体。

## 四、异常：两个类，一个用途

| 类 | 继承 | 干什么 | 谁抛 |
|---|---|---|---|
| `TaskError(Exception)` | `Exception` | 所有业务错误的**基类**，空类体，只负责"分类" | 子类 |
| `TaskNotFoundError(TaskError)` | `TaskError` | 编号不存在；`__init__` 把 `task_id` 存成属性 | `TaskStore.get()` |

为什么两个：调用方想"让用户重新输入"抓 `TaskError` 就够了；想区分"找不到编号"单独抓 `TaskNotFoundError`。`e.task_id` 能拿到原始编号。

## 五、模块级函数

| 函数 | 签名要点 | 干什么 | 谁调用 |
|---|---|---|---|
| `_now()` | `-> str` | `datetime.now().isoformat(timespec="seconds")` | `Task.created_at` 的默认工厂 |
| `parse_due(due)` | 收 `str \| None`，返回 `str \| None` | 空 → `None`；合法 → 归一化 `YYYY-MM-DD`；非法 → 抛 `TaskError` | `add()`、`edit()`（参考版） |

## 六、`Task` 类

**字段**（顺序不能乱，无默认值的必须在前面）：

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `id` | `int` | 无 | 编号，永不复用 |
| `title` | `str` | 无 | 标题 |
| `due` | `str \| None` | `None` | 截止日，`YYYY-MM-DD` |
| `course` | `str \| None` | `None` | 课程 |
| `done` | `bool` | `False` | 是否完成 |
| `created_at` | `str` | `field(default_factory=_now)` | 创建时间（现算） |

**方法**：

| 方法 | 干什么 | 依赖谁 | 谁调用 |
|---|---|---|---|
| `days_left(today=None)` | 返回距截止还有几天（负=逾期，`None`=没截止日） | `date.fromisoformat` | `describe()`、`upcoming()`、测试 |
| `describe(today=None)` | 一行人类可读文本 | `self.done`、`self.due`、`days_left()` | 命令行、网页、给模型看的工具结果 |

> 两个方法都有 `today` 参数：**依赖注入**，为了测试能固定"今天"，否则断言"还剩 2 天"明天就红。

## 七、`TaskStore` 类

**实例属性**：`self.path`（Path）、`self.tasks`（`list[Task]`）。

| 方法 | 读写 | 干什么 | 容易漏的点 |
|---|---|---|---|
| `__init__(path)` | 读 | 存 path、`self.tasks = self._load()` | 对象一存在，内存就必须等于磁盘 |
| `_load()` | 读文件 | 三个情况：文件不存在→`[]`、空文件→`[]`、正常→`[Task(**d)]` | 空文件不处理会 `json.loads("")` 崩 |
| `_save()` | 写文件 | `asdict` 转字典 → `dumps` → 写 `.tmp` → `replace` | 先临时文件再替换，防写一半毁原文件 |
| `get(id)` | 内存 | 按 id 取一条，找不到抛 `TaskNotFoundError` | 别返回 `None`（调用方会 `AttributeError`更远） |
| `list(include_done, course)` | 内存 | 过滤 + 排序，返回**新**列表 | 排序 key 是三元组；不要原地 `sort` |
| `upcoming(days, today)` | 内存 | `days` 天内到期的未完成任务（含逾期） | 复用 `self.list()`，别重写过滤 |
| `add(title, due, course)` | 内存+文件 | 校验标题 → 分配 `max(id)+1` → `parse_due` → append → `_save` | 编号用 max+1，不是 len+1 |
| `complete(id)` | 内存+文件 | `get` 拿到 → `done=True` → `_save` | 别替换成新对象，改属性 |
| `delete(id)` | 内存+文件 | `get` 拿到 → 从列表移除 → `_save` | 返回被删对象，方便回显 |

**规律**：改数据的方法（add/complete/delete）末尾**必须有 `_save()`**；只读的方法一律不碰磁盘。

## 八、数据流

```
启动：  path ─► _load() ─► json.loads(文本) ─► [Task(**d)] ─► self.tasks
                                                                    │
增删改：  add/complete/delete ─► 改 self.tasks ─► _save()            │
                                                    │               │
                                                    ▼               │
                                    asdict → dumps → 写 .tmp → replace（原子替换）
                                                                    │
查询：  get/list/upcoming ◄──────────────────────────────────────────┘
                │
                ▼
            Task.describe() ─► 一行文本（给人 / 给模型）
```

## 九、为什么这样分层（三条）

1. **数据层不 print**：`describe()` 返回字符串，谁要显示谁自己 print。这样命令行、网页、模型工具三个界面能共用同一份格式。
2. **校验只有一个入口**：`parse_due` + `add` 里集中校验，任何界面都绕不过去。
3. **异常代替返回值**：`return -1` 常被调用方忽略；异常不接就崩，逼你面对。

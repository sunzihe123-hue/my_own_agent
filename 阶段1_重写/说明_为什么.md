## 四、每个部件为什么存在

这一节就是你说的"有些函数不知道为什么需要它"。

### 4.1 为什么要有那两个异常类

| 部件 | 不写它会怎样 | 说明 |
|---|---|---|
| `TaskError(Exception)` | 调用方要 `except ValueError` / `except KeyError` / `except ...` 逐个猜 | 它是一个"分类标签"，空类体就够了。所有业务错误都从它派生，调用方一句 `except TaskError` 全接住 |
| `TaskNotFoundError(TaskError)` | 想提示"没有 #7 这条，要不要看看 #1-#5"时，只能对着报错字符串抠数字 | 它在 `__init__` 里把 `task_id` 存成**属性**，调用方 `e.task_id` 直接拿到原始编号 |
| `super().__init__(f"找不到编号为 {task_id} 的任务")` | `str(e)` 是空的，日志里看不出是哪条 | 异常对象本身要带一句人话 |

> C 对照：这是 `return -1` 的进化版。C 里返回 -1，调用方**经常忘了检查**，程序带着脏数据继续跑；
> 异常一旦抛出，没人接就当场崩，逼你面对。而且异常自带"是什么错、错在哪个编号"的完整信息。

### 4.2 为什么用 `dataclass`

不写 `@dataclass`，你就得手写：

```python
def __init__(self, id, title, due=None, ...):
    self.id = id
    ...         # 6 行赋值
def __repr__(self): ...   # 不然 print(task) 只显示 <Task object at 0x...>
def __eq__(self, other): ...  # 不然测试里没法直接比较两个 Task
```

`@dataclass` 自动生成这三样。**收益**：加一个字段只改一行；测试挂了 `print(t)` 能直接看到全部字段。

> C 对照：`dataclass` ≈ `struct`，但 Python 会替你把 `init` 和"printf 格式"都生成好。

### 4.3 `_now()` 和 `field(default_factory=_now)` 为什么要拆成两个

这是全篇最值得记住的一个坑：

```python
created_at: str = _now()          # ❌ 错
created_at: str = field(default_factory=_now)   # ✅ 对
```

错的那个：`_now()` 在**类定义时**就被调用了一次，于是**所有任务共享同一个创建时间**。
`default_factory` 存的是"函数本身"，每次 `Task(...)` 才调用一次。

> 你 474 行版本里 `TaskStore.__init__` 用了 `list(tasks or [])` 而不是 `tasks or []`，
> 防的是**同一个病**：可变默认值/提前求值的默认值被所有实例共享。

**动手玩一下**（第 2 步做完之后）：把 `default_factory=_now` 故意改成 `=_now()`，跑
`test_created_at_is_filled`，看它怎么挂，再改回来。挂一次比看十遍记得牢。

### 4.4 `parse_due()` 为什么单独一个函数（而不是写在 `add` 里）

`add()` 里当然可以直接写 `date.fromisoformat()`，但那样有两个问题：

1. **将来 `edit()` 也要校验日期**（你 474 行版本里就有 edit），写两遍，改规则时必然漏改一处；
2. 校验规则和错误提示会散在好几处。

所以：**校验只在一个地方做**，谁要加任务都必须过这一关。参考版把它写成公开的 `parse_due`（前面没下划线），
因为它本身就是有用的能力；你 474 行版本写成 `_normalize_due`（下划线）表示"内部用"。
两者都对，只是"要不要给外界直接用"的选择。

它还干第二件事：**归一化**。`"20261020"` 存进去变成 `"2026-10-20"`，
这样后面排序、比较字符串时不用再考虑格式变体。

> ⚠️ **顺手纠个错**：你 474 行版本 `_normalize_due` 的注释里写着
> "`fromisoformat` 把 `2026-1-4` 规范成 `2026-01-04`"——这句是**错的**。
> 实测（Python 3.13）：
>
> | 输入 | `date.fromisoformat` 结果 |
> |---|---|
> | `"2026-1-4"` | ❌ `ValueError`（ISO 要求月、日补零） |
> | `"20261020"` | ✅ `2026-10-20`（紧凑格式反而认） |
> | `"2026-10-20"` | ✅ |
> | `"2026/10/20"` | ❌ `ValueError` |
> | `"2026-10-20T00:00:00"` | ❌ `ValueError`（那是 `datetime.fromisoformat` 才认的） |
>
> 所以 `parse_due("2026-1-4")` 应该**抛错**，而不是被悄悄改成 `2026-01-04`。
> 用户手写 `2026-1-4` 时，你希望他立刻知道格式不对，还是被默默改掉？这是产品决定，不是语法问题。
> 参考版的实现选的是"抛错"，`test_unpadded_month_is_rejected` 就是这条规矩。

### 4.5 为什么存字符串而不是 `date` 对象

因为要写进 JSON，而 **JSON 只认字符串/数字/布尔/null**。
存 `date` 对象的话，每次存要转一次、每次读要转回来，多一层转换就多一个 bug 点。
需要计算时临时 `date.fromisoformat(self.due)` 转一下就行。

### 4.6 为什么 `days_left()` 和 `describe()` 要一个 `today` 参数

```python
def days_left(self, today: date | None = None) -> int | None:
```

如果不收这个参数、函数体里直接 `date.today()`，测试就写不出来了：
今天断言"还剩 2 天"，明天跑就变 1 天，**测试过一夜自己就红了**。

传进去叫**依赖注入**：逻辑不变，只把"现在几点"这个不稳定因素从外面递进来。
`today or date.today()` 表示"不传就用真的今天"。

### 4.7 为什么 `describe()` 返回字符串，而不是直接 `print`

因为要展示任务的地方不止一个：命令行、网页、给大模型看的工具结果。
谁 `print` 谁就被绑死在终端上，网页那边只能重抄一份格式。
**格式写在数据对象上，到处复用。**

### 4.8 为什么 `TaskStore` 要在 `__init__` 里就读文件

```python
def __init__(self, path):
    self.path = Path(path)
    self.tasks: list[Task] = self._load()
```

这样保证一个铁律：**`TaskStore` 对象一旦存在，它内存里的数据就等于磁盘上的数据**。
你就不会遇到"这个 store 是新的，那个是旧的"的分裂状态。
测试里想验证"真的存进去了"，做法就是**再 new 一个 `TaskStore(同一个 path)`**，
它必须能读出刚才写的——`test_add_is_persisted` 就是这么验的。

### 4.9 `_load()` 里的两个边界

```python
if not self.path.exists(): return []      # 第一次运行，文件还不存在
if not text.strip(): return []            # 文件被创建了但是空的
```

不写第二个，第一次运行就会 `json.loads("")` 炸掉（空串不是合法 JSON）。
**写持久化的代码，一半的工作量在处理"文件不存在/是空的/是坏的"这三种情况。**

`Task(**d)` 那个 `**`：把 `{"id":1,"title":"x"}` 拆成 `Task(id=1, title="x")`。
键名必须和字段名**逐字相同**，所以改字段名要两边一起改，否则这里直接 `TypeError`（早暴露，是好事）。

### 4.10 `_save()` 为什么要先写 `.tmp` 再 `replace`

```python
tmp.write_text(...)     # 先写临时文件
tmp.replace(self.path)  # 再一次性替换
```

如果直接 `open(path, "w")` 往正式文件里写，**写到一半断电/崩了，原文件就被截断了**，
下次启动读出来是半截 JSON → 所有任务全丢。

先写临时文件、写完再替换，坏也只会坏临时文件，正式文件永远是完整的旧版本。
（Redis 保存 `dump.rdb`、数据库的 WAL 用的是同一个思路。）

### 4.11 `get()` 为什么抛异常而不是返回 `None`

返回 `None` 的话，调用方下一行 `t.title` 会抛 `AttributeError: 'NoneType' object has no attribute 'title'`，
**报错位置离真正原因（编号不存在）隔了三层函数**，查起来要命。
抛 `TaskNotFoundError` 则是：错在出事的瞬间暴露，消息直接说"找不到编号为 42 的任务"。

### 4.12 `list()` 的三个细节

| 细节 | 为什么 |
|---|---|
| `include_done: bool = False` | 待办清单默认只看没做完的。注意你 474 行版本默认是 `True`，参考版是 `False` —— 你看的是哪个版本的默认值，决定了所有界面的默认行为 |
| 返回新列表而不是就地 `sort()` | 就地排会改掉 `self.tasks` 的顺序，调用方只是"看一眼"却把内部状态改了，后面出问题没法追 |
| 排序键 `(t.due is None, t.due or "", t.id)` | 三项依次比较：① `due is None` 的 `False`(0) 排在 `True`(1) 前面 → **有截止日期的在前**；② `t.due or ""` 把 `None` 变成空串，避免 `None` 和 `str` 比较报 `TypeError`；③ `t.id` 兜底，保证结果稳定（同样的输入永远同样顺序） |

### 4.13 `upcoming()` 的两个语义决定

| 决定 | 为什么 |
|---|---|
| **包含已逾期** | 逾期任务比未来任务更紧急，排除掉正好漏掉最该处理的 |
| **跳过已完成的** | 做完了的不需要再提醒 |

它还直接复用了 `self.list()`，而不是自己再写一遍过滤——**过滤规则只有一份**，
以后"默认隐藏已完成"的规则要改，`upcoming` 跟着自动变。

### 4.14 `add()` 里编号为什么是 `max(...)+1`

用 `len(self.tasks) + 1` 的话：删掉 #2 之后长度退回 2，下一条又会拿到 2，**和历史编号撞车**。
`max((t.id for t in self.tasks), default=0) + 1` 让编号只增不减，永不复用。
`default=0` 是为了空列表时 `max()` 不抛 `ValueError`，让第一条从 1 开始。

`(t.id for t in ...)` 是生成器表达式，不会先在内存里造一个新列表（你 474 行版本的注释里也写了这点）。

### 4.15 `complete()` / `delete()` 末尾那行 `self._save()`

`add` / `complete` / `delete` 三个改数据的方法，**每个末尾都必须有 `_save()`**。
漏一个不会报错，只会在你下次启动程序时发现"数据少了一条"。
`test_complete_is_persisted` 和 `test_delete_returns_task_and_persists` 专门抓这个。

推论：**`_save()` 是"写入口"，谁改了 `self.tasks` 谁负责存盘。** 这是一条要靠纪律守住的约定。

## 五、你一定会踩的 4 个坑

1. **`created_at: str = _now()`** —— 见 4.3。所有任务共享同一时间。
2. **忘了某处 `_save()`** —— 见 4.15。改完不存，重启后数据消失。
3. **`_load` 里没有处理空文件** —— 见 4.9。第一次运行或文件被清空后直接崩。
4. **`_save` 里用 `json.dump(data, f)` 写成 `json.dumps(data, f)`** ——
   `dumps` 是"返回字符串"，`dump` 是"写进文件对象"。你之前 `参考task.py` 就在这里错了。

## 六、C 程序员对照表

你是学 C 的，这张表能省不少时间：

| Python | C 里对应什么 | 关键差别 |
|---|---|---|
| `@dataclass` | `struct` | 自动生成构造、打印、相等比较 |
| `list` | 手写的动态数组 / 链表 | 自带增删查、自动扩容 |
| `raise` / `except` | `return -1` + 每层 `if (ret < 0) return ret;` | 异常不会被静默忽略 |
| `Path` | `char path[]` + `sprintf` + `access()` | 自动处理 Windows/Unix 分隔符，`.exists()`、`.parent` 都是方法 |
| `dict` | 哈希表（自己实现） | 语言内建 |
| `None` | `NULL` | 但 `None` 是对象，`t.due is None` 胜过 `t.due == None` |
| `for x in list` | `for (i=0;i<n;i++)` | 不用管下标和越界 |
| `with open(...) as f` | `FILE *f = fopen(); ... fclose(f);` | 离开缩进自动关文件，异常时也关 |

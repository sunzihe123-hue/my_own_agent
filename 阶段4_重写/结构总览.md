# 阶段 4 结构总览：测试层 + 日志

> 这张图回答三个问题：**有哪些东西？谁调用谁？为什么需要它？**
> 代码在 `阶段4_重写/support.py`（测试支撑）+ `阶段3_重写/agent.py`（本阶段只加了 3 处日志）；
> 验收在 `test_tools.py`（4 条）+ `test_agent_log.py`（2 条）；设计理由在 `说明_为什么.md`。

## 一、一眼看全

```
项目根/
├── 阶段3_重写/                     ← 被测代码（不复制、不改造，只加日志）
│   ├── tools.py                    ToolRegistry / Tool（测试对象 1）
│   └── agent.py  ★阶段 4 加 3 处日志（测试对象 2）
│
└── 阶段4_重写/                     ← 测试层（这一阶段写的只有这些）
    ├── support.py                  sys.path 破例 + TmpDirTest + build_registry
    │                               + FakeToolClient + capture_logs
    ├── test_tools.py               4 条：schema 必填/类型/描述、execute 返回字符串、默认值
    ├── test_agent_log.py           2 条：日志里有"工具名+参数"、有"结果"
    ├── 说明_为什么.md              每个部件"删了会怎样"
    └── 结构总览.md                 本文件
```

**一句话**：`support.py` 负责"让测试能离线跑、能把日志抓下来"，两个 `test_*.py` 负责"断言"，`agent.py` 的日志是被断言的对象。

```
test_tools.py ──┐
                ├──→ support.py ──(sys.path.insert)──→ 阶段3_重写/tools.py
test_agent_log.py ┘        │                                └→ 阶段3_重写/agent.py
                           ├── TmpDirTest      ← 每个测试一个临时目录
                           ├── build_registry  ← add / hello 两个工具（fixture）
                           ├── FakeToolClient  ← 离线假客户端
                           └── capture_logs    ← 把日志重定向进临时文件
```

## 二、文件头：import 了什么，为什么

| 文件 | 写法 | 导入的东西 | 干什么 | 不导入会怎样 |
|---|---|---|---|---|
| `support.py` | `from __future__ import annotations` | （编译开关） | 注解延迟成字符串，可以写 `list[dict]` / `str \| None` | 旧语法在低版本 Python 报错 |
| | `import logging` | 日志 | `getLogger()` / `FileHandler` / `Formatter` | `capture_logs` 无从下手 |
| | `import sys` | 解释器设施 | `sys.path.insert` 把 `阶段3_重写` 加进搜索路径 | `import tools` 直接 ModuleNotFoundError |
| | `import tempfile` | 临时目录 | `TemporaryDirectory()` 给每个测试一个干净目录 | 测试会往项目里写垃圾、互相污染 |
| | `import unittest` | 测试框架 | `TestCase` / 各种 `assert*` | 写不了测试 |
| | `from pathlib import Path` | 路径对象 | `Path(__file__).resolve().parent.parent` 算绝对路径 | 用相对路径的话，cwd 一变就崩 |
| | `from types import SimpleNamespace` | 简易对象 | 捏"像真 SDK"的替身 | `FakeToolClient` 造不出 `.chat.completions.create` |
| | `from tools import ToolRegistry` | 被测模块 | 建注册表 + 类型标注 | 造不出 fixture |
| `test_tools.py` | `import unittest` | 测试框架 | `TestCase` / `assert*` | —— |
| | `from support import build_registry` | 本目录模块 | 拿 add / hello 两个工具 | 每条测试都要自己造一遍 |
| `test_agent_log.py` | `from support import FakeToolClient, TmpDirTest, build_registry, capture_logs, model_msg, tool_call` | 本目录模块 | 假客户端 + 临时目录 + 日志重定向 + 剧本助手 | 同上 |
| | `from agent import Agent` | 被测模块 | 真的跑一遍 agent 循环 | 测不了日志 |

> **import 顺序有讲究**：`from support import ...` 必须写在 `from tools import ...` / `from agent import ...` **之前**，
> 因为 `sys.path` 是在 `support.py` 被 import 时插进去的（Python 按顺序执行 import）。

## 三、部件表

### support.py

| 名字 | 类型 | 干什么 | 谁用它 |
|---|---|---|---|
| `PHASE3_DIR` | 常量 | `阶段3_重写` 的绝对路径 | 下面的 `sys.path.insert` |
| `TmpDirTest.setUp()` | 方法 | 建临时目录，存成 `self.dir` | 每个日志测试运行前自动调用 |
| `TmpDirTest.tearDown()` | 方法 | 删掉临时目录 | 每个日志测试运行后自动调用（失败也调用） |
| `build_registry()` | 函数（fixture） | 造注册了 `add` / `hello` 的注册表 | 两个测试文件 |
| `tool_call(call_id, name, arguments)` | 函数（已给） | 捏一个 `tool_call` 对象（`.id` / `.function.*`） | 剧本 |
| `model_msg(content, calls)` | 函数（已给） | 捏一条模型回复（`.content` / `.tool_calls`） | 剧本 |
| `FakeToolClient.__init__` | 方法 | 存剧本、存 `calls`、把 `self.chat.completions.create` 指向 `_create` | 测试里 `FakeToolClient(剧本)` |
| `FakeToolClient._create` | 方法 | 记一笔请求，从剧本弹一条回复，包成 `.choices[0].message` | `Agent._call_model()` |
| `capture_logs.__init__` | 方法 | 准备 `FileHandler`（写临时目录的 `.log`），记住 root 原 level | `with capture_logs(...)` |
| `capture_logs.__enter__` | 方法 | 给 root 挂 handler、调 level，返回文件路径 | `with ... as log_path` |
| `capture_logs.__exit__` | 方法 | 摘 handler、close、恢复 root level | `with` 块结束时自动调用 |

### 阶段3_重写/agent.py（本阶段只加日志）

| 位置 | 加什么 | 用途 |
|---|---|---|
| `chat()` 每轮开头 | `log.info("第几轮 + 历史条数")` | 还原"模型当时看到的对话长度" |
| `chat()` 工具执行前 | `log.info("工具名 + arguments")` | 断言点 ①（test_agent_log 第 5 条） |
| `chat()` 工具执行后 | `log.info("工具名 + result")` | 断言点 ②（test_agent_log 第 6 条） |
| `_call_model()` 异常分支 | `log.exception("...")` + `raise` | 保留完整调用栈，且不吞异常 |

## 四、数据流 1：一条日志测试从 Run 到绿

`test_agent_logs_tool_result`：

```
Run test_agent_log.py
  │
  ├─ 模块 import：support（插入 sys.path）→ agent / tools 可用
  │
  ├─ [TmpDirTest.setUp]  建临时目录 self.dir = C:\...\Temp\tmpXXXX
  │
  ├─ FakeToolClient(剧本)
  │     剧本[0] = model_msg(calls=[tool_call("call_1", "add", '{"a": 2, "b": 3}')])
  │     剧本[1] = model_msg(content="都算完了")
  │
  ├─ with capture_logs(self.dir / "agent.log")：
  │      给 root 挂 FileHandler("agent.log")，root level = DEBUG
  │
  ├─ agent.chat("算一下")
  │     ① log.info("第 1 轮请求，历史 2 条")          → 写进文件
  │     ② 第 1 次请求 → 剧本[0]：有 tool_calls
  │     ③ log.info("调用工具 add，参数 {...}")         → 写进文件
  │     ④ registry.execute("add", '{"a": 2, "b": 3}') → "5"
  │     ⑤ log.info("工具 add 返回 5")                  → 写进文件
  │     ⑥ 第 2 次请求 → 剧本[1]：纯文本 → return "都算完了"
  │
  ├─ with 结束 → __exit__：摘 handler + close（日志此刻全部落盘）+ 恢复 level
  │
  ├─ text = log_path.read_text(encoding="utf-8")
  ├─ assertIn("5", text)          → 绿
  │
  └─ [TmpDirTest.tearDown]  删临时目录（日志文件一起没）
```

## 五、数据流 2：日志从 `log.info` 到断言的那条路

```
agent.py: log.info("工具 %s 返回 %s", name, result)
              │
              ▼
        Logger("agent")                     ← log = logging.getLogger(__name__)
              │  level = NOTSET → 继承 root
              │  propagate = True（默认）
              ▼
        root Logger                         ← capture_logs.__enter__ 里 setLevel(DEBUG)
              │
              ▼
        Handler（capture_logs 挂的 FileHandler）  ← 换出口就是在这里换的
              │  Formatter("%(levelname)s %(name)s %(message)s")
              ▼
        tmpXXXX/agent.log                   ← 测试读它 → assertIn("5", text)
```

**要点**：业务代码只认 `log`，从不认"输出到哪"。所以日志天然可测、可换目的地——这是它比 `print` 强的地方。

## 六、验收对照（6 条 ↔ 部件）

| # | 测试 | 断言什么 | 测的是哪个部件 |
|---|---|---|---|
| 1 | `test_add_tool_schema_required` | `required == ["a","b"]`；`a`/`b` 类型 `integer`；描述在 | `Tool.schema()`（阶段 3） |
| 2 | `test_execute_add_returns_string` | `execute("add", '{"a": 2, "b": 3}')` 是字符串 `"5"` | `ToolRegistry.execute()` |
| 3 | `test_hello_schema_has_description` | 工具描述 + 参数描述都在 | `Tool.schema()` |
| 4 | `test_hello_uses_default_arg` | `execute("hello", "{}") == "你好，同学"`；`required == []` | `execute()` + schema 的必填规则 |
| 5 | `test_agent_logs_tool_call` | 日志全文有 `add` 和 `{"a": 2, "b": 3}` | `agent.py` 日志②-a |
| 6 | `test_agent_logs_tool_result` | 日志全文有 `5` | `agent.py` 日志②-b |

> 另外：**阶段 3 的 28 条必须仍然全绿**——加日志是"只加观测"，不能改行为。这就是回归测试。

## 七、判卷对照（AI 会故意改坏的地方）

判卷（mutation testing）= 改坏一处实现 → 对应的测试**必须变红**；还是绿，说明测试没抓住。

| 改坏什么 | 该红的测试 | 为什么 |
|---|---|---|
| 删掉 schema 里的参数 `description` | 1、3 | 断言描述存在 → 拿不到 key 直接 ERROR |
| 工具描述不传进 `Tool`（`description` 空） | 3 | 工具描述的断言 |
| `execute()` 不转字符串，直接 `return result` | 2 | `assertEqual(..., "5")` 和 `assertIsInstance(str)` 都失败 |
| 有默认值的参数被写进 `required` | 4 | `required == []` 失败（模型会硬塞参数，默认值失效） |
| 工具执行前的日志只记名字、不记参数 | 5 | 参数断言失败 |
| 删掉"工具结果"那条日志 | 6 | 结果断言失败 |
| 把 `_call_model` 的 `raise` 去掉 | ——（本轮 6 条不覆盖） | 已知限制：异常分支留到阶段 5 补测 |

> 判卷时每次只改一处，跑完立刻恢复（`git diff` 或备份），否则会分不清哪条红是哪处坏引起的。

## 八、这一步的三条设计取舍

1. **测试层横切，不复制业务代码**：`sys.path.insert` 破例，是为了让测试验的是**真代码**；把代码抄一份进 `阶段4_重写/` 就成了"验证抄件"。
2. **日志当输出测**：不拦 `print`、不改业务代码，而是换 `Handler` 换出口；观测手段和被观测代码解耦。
3. **判卷作为测试质量的硬标准**：绿不等于对——只有"改坏必红"才能证明测试真的在保护代码。
